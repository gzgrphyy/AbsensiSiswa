# UI/UX Design Plan - Absensi Sekolah

## 1. Design System

### Color Palette
- Primary: `#1F2937` (dark gray)
- Secondary: `#F3F4F6` (light gray)
- Accent Blue: `#3B82F6`
- Success: `#10B981`
- Warning: `#F59E0B`
- Danger: `#EF4444`
- Background: `#FFFFFF`
- Surface: `#FFFFFF` (cards)

### Typography
- Font: System UI (Inter, Roboto)
- H1: 24px, font-bold
- H2: 20px, font-semibold
- Body: 16px, regular
- Line height: 1.5

### Spacing
- Base unit: 4px
- Scales: 4, 8, 12, 16, 20, 24, 28, 32, 36, 44, 52

### Shadows
- `shadow-sm` (light)
- `shadow` (medium)
- `shadow-lg` (strong)

### Border Radius
- `rounded-sm` (4px)
- `rounded` (6px)
- `rounded-lg` (8px)

### Button Styles
- Primary: bg-primary text-white rounded, hover:bg-primary/90
- Secondary: bg-secondary text-primary rounded
- Outline: border-2 border-primary text-primary rounded hover:bg-primary/10
- Danger: bg-danger text-white rounded hover:bg-danger/90

### Badge Styles
- Success: bg-success text-white rounded
- Warning: bg-warning text-gray-800 rounded
- Danger: bg-danger text-white rounded

### Layout
- Header: fixed top, full width, shadow, padding 8
- Sidebar: fixed left, width 240px (desktop), collapsible on mobile, padding 16
- Main Content: flex-1, padding 16, max-w-6xl
- Footer: optional, small, text-gray-500

## 2. Reusable UI Components

| Component | Description | Key Props / Variants |
|-----------|-------------|---------------------|
| `AppLayout` | Root layout with Header, Sidebar, MainContent | `showSidebar` (bool) |
| `Sidebar` | Vertical navigation, collapsible, role-based items | `collapsed` (bool) |
| `Header` | Top bar with logo, user menu, notifications | `hasNotifications` (bool) |
| `Card` | Container with shadow, padding, rounded corners | `title`, `footer` |
| `Table` | Responsive data table, sortable, pagination | `columns`, `data`, `editable` |
| `Badge` | Small status label | `type` ('success','warning','danger') |
| `Button` | Primary, secondary, outline, danger | `variant` ('primary','secondary','outline','danger') |
| `Form` | Input group with label, placeholder, validation | `model`, `fields` |
| `Modal` | Centered dialog with backdrop | `title`, `content`, `onClose` |
| `NavLink` | Active link styling for sidebar | `to` (route) |
| `DataTable` | Specialized table for master data (guru, siswa, kelas) | `source`, `columns` |

## 3. Page Structure

### Auth
- `Login.vue` – existing, no changes needed.

### Dashboard Admin
- `DashboardAdmin.vue` – grid of statistic cards (guru, siswa, kelas, hadir, sakit, izin, alpha, persentase, siswa_alpha, monitoring, aktivitas)
- `MasterDataAdmin.vue` – pages for each master entity (Guru, Siswa, Kelas, TahunAjaran, Semester, Ruangan, JadwalPelajaran) using `DataTable` component.
- `RekapAbsensiAdmin.vue` – table of attendance summary.

### Dashboard Guru
- `DashboardGuru.vue` – class list, active class badge, live attendance list (table with status badges), QR scan button.
- `AbsensiGuru.vue` – date picker, class selector, table of students with status badges, confirm attendance modal.

### Dashboard Siswa
- `DashboardSiswa.vue` – status absen hari ini, QR scan button, status terakhir, riwayat singkat.

### Data Master Admin
- `MasterDataAdmin` pages: each uses a consistent table layout with filters and bulk actions.

### Absensi Guru
- `AbsensiGuru.vue` – formal table with badge colors, confirm attendance flow.

### Scan QR Siswa
- `ScanSiswa.vue` – QR scanner component (maybe using a library), list of nearby students, status indicator.

### Riwayat Absensi
- `RiwayatAbsensi.vue` – list of attendance records with filters (date, class).

### Rekap Absensi
- `RekapAbsensi.vue` – summary table or simple chart (e.g., using `vue-chartjs`).

### Export Laporan
- `ExportLaporan.vue` – buttons for CSV/PDF export, possibly modal for export options.

## 4. Navigation & Role Routing

- Use existing `auth.global.ts` middleware for role-based routing:
  - ADMIN → `/admin/*`
  - GURU → `/absensi/*`, `/siswa/*`
  - SISWA → `/siswa/*`
- Sidebar items should reflect role permissions (e.g., Admin sees all master data pages, Guru sees only classes and attendance, Siswa sees personal data).

## 5. Mock Data & Development Approach

- Use existing API endpoints for real data; for initial UI development, mock data can be stored in local state (Pinia) or placeholder arrays.
- Implement components in a modular way to allow easy swapping of mock data with real API calls later.
- Follow desktop-first responsive design: sidebar collapses to icon-only on <768px, header becomes sticky, content stacks.

## 6. Implementation Phases

1. **Design System Setup** (1 day)
   - Define Tailwind colors, spacing, typography in `tailwind.config.ts` or separate CSS.
2. **Component Library** (3-4 days)
   - Build `AppLayout`, `Sidebar`, `Header`, `Card`, `Table`, `Badge`, `Button`, `Form`, `Modal`, `NavLink`.
   - Ensure all components are reusable and follow design system.
3. **Page Skeletons** (2 days)
   - Create skeleton pages for each dashboard and master data page using the layout and components.
4. **Mock Data Integration** (1 day)
   - Populate pages with mock data to verify layout and interaction.
5. **Refine UI per Role** (2 days)
   - Adjust colors, spacing, and component variants to match formal (Admin) vs friendly (Guru) vs simple (Siswa) styles.
6. **Responsive & Accessibility** (2 days)
   - Test collapsible sidebar, mobile friendliness, focus states, contrast.
7. **QA & Validation** (1 day)
   - Visual consistency check across all pages, role-based access verification, responsive behavior.

## 7. Validation & QA

- Verify that each role can only access its authorized pages.
- Ensure consistent spacing, typography, and color usage across all components.
- Test responsive behavior on mobile, tablet, desktop.
- Conduct peer review of UI components for reusability.
